## 文件职责

- `data/index.js`：主要数据出口。`data/schedules.js`修订后的日程会覆盖基础时间轴，改时间不能只改旧字段。
- `data/guide.js`：逐日景点、动漫点、来源和说明；`data/food.js`与`data/meal-stops.js`：餐厅、时段、路线与预算。
- `data/places.js`、`data/routes.js`：地点、坐标、分段路线；`data/stays.js`：住宿硬约束；`data/trip.js`：航班预算。
- `data/checklist.js`：确认进度与版本；`data/preparation.js`：打包清单、出门卡等；`data/insurance.js`：保险摘要。
- `data/photos.json`、`data/transit-photos.js`：图片对应、作者和授权；图片原件在`assets/images/`。
- `assets/app.js`：启动、状态、导航、地图和整体渲染；`assets/day-route.js`：每天路线时间轴及餐厅联动。
- `assets/offline-kit.js`：急用卡、当地联系方式、本机二维码、离线HTML生成器。
- `assets/compact.css`：当前主视觉覆盖；旧CSS仍有继承，删除前检查引用。
- `android/`：原生Android外壳；`scripts/prepare-android.mjs`：把网页、急用页、交接资料准备成APK资源。
- `scripts/export-handoff.mjs`：生成可在手机阅读的完整工程交接与原始源文件目录。
- `scripts/build-android.sh`：准备资源、Gradle构建；签名和SDK配置从环境变量/本机配置读，不提交密钥。
- `.github/workflows/deploy-pages.yml`：main推送自动发布GitHub Pages。

## 接手后如何运行和修改

1. `source/`即完整可编辑项目。安装Node.js22+，进入源码目录执行`npm ci`。
2. 本机预览：`npm run dev`，打开localhost:5173；打包：`npm run build`。
3. 网站发布：`VITE_BASE_PATH=/osaka-around/ npm run build`；交接阅读包：`npm run handoff`。main推送自动部署。
4. 数据验证：`node scripts/validate-trip.mjs`；常规完整性：`git diff --check`。关注餐厅路线、图片无重复、15天14晚、住宿不变。
5. APK资源：`npm run android:prepare`。标准版不含二维码；私人版需设置`TRIP_PRIVATE_QR`为私人二维码PNG路径。
6. Android使用JDK17、AndroidSDK36/Build Tools36.0.0、Gradle8.13。复制环境示例并填本机路径；`android/local.properties`只属于本机。
7. 正式签名需`TRIP_KEYSTORE`、`TRIP_KEYSTORE_PASSWORD`，别更换既有签名。构建：`npm run android:build`。
8. 更新时递增`versionCode`，保留相同包名与签名；否则安卓不能覆盖原应用。不要让用户为更新先卸载，以免丢本机二维码和勾选。
9. 若需接手完整Git历史，私人交付目录另有`工程历史.bundle`，可用`git clone 工程历史.bundle source-history`恢复；旅行内容文本与普通源码目录不包含Git历史。

## APK行为与边界

- 安装包内置网页攻略、照片、急用HTML、交接阅读页；地图底图及外部AI需要网络。
- 离线启动首先显示独立急用HTML，不靠整站JS成功启动。固定入口可返回本地攻略。
- GoogleMaps使用通用URL和Android外部Intent；安装了Maps则优先打开，否则系统浏览器。
- 翻译按钮复制中日口译提示词，再尝试启动Gemini/ChatGPT，未安装则打开官网。不是应用内自动连续录音翻译，不申请麦克风或相机权限。
- QR存储只在本机；标准版可通过急用页的“导入/更换二维码”入口加入。私人版的默认QR在APK资源内，仍不上传公开仓库。
- HTML的网页下载/浏览器打印与原生WebView行为不同；APK入口使用内置文件，手机浏览器仍可下载网页离线HTML。
- APK在没有接入用户手机的情况下只能完成构建、静态检查与可用设备上的验证。实机安装、外部App关联、HyperOS限制不能假称已验证。
